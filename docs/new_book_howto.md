# Как подготовить другую двуязычную книгу

Программа работает не только с «Книгой Урантии»: любую книгу, у которой есть два языка и абзацы можно сопоставить попарно, можно превратить в базу для поиска, вопросов и проверки перевода. Нужен один файл со списком абзацев.

## 1. Формат файла (JSON)

Один файл `.json`, в нём **массив** записей. Каждая запись — один абзац в двух языках:

```json
[
  {
    "id": "1:1.1",
    "paper": 1,
    "section": 1,
    "paragraph": 1,
    "en": "In the beginning ...",
    "ru": "В начале ..."
  },
  {
    "id": "1:1.2",
    "paper": 1,
    "section": 1,
    "paragraph": 2,
    "en": "...",
    "ru": "..."
  }
]
```

Обязательные поля (все шесть):

| Поле | Что это | Правила |
|---|---|---|
| `id` | уникальный номер абзаца | строго в виде `Глава:Раздел.Абзац`, например `147:2.4` (три целых числа, двоеточие и точка) |
| `paper` | номер главы (в Урантии — «Paper») | целое число, **совпадает** с первым числом в `id` |
| `section` | номер раздела внутри главы | целое число (0 допустимо), совпадает со вторым числом |
| `paragraph` | номер абзаца внутри раздела | целое число, совпадает с третьим числом |
| `en` | текст на английском | строка |
| `ru` | текст на русском | строка |

Важно:

- Записи должны идти **в порядке чтения книги**: по порядку записей программа определяет «предыдущий/следующий абзац» и контекст.
- Если в книге нет глав или разделов, используйте `1` (или `0`) вместо них, например `1:1.1`, `1:1.2`, … — главное, чтобы `id` был в формате `N:N.N` и не повторялся.
- Нужны оба языка. Если у абзаца нет перевода, оставьте пустую строку `""` (но хотя бы один из двух текстов должен быть непустым — иначе запись пропускается).
- Файл в кодировке **UTF-8**.
- Некорректные записи не останавливают сборку: они пропускаются, а причина записывается в `logs\index.log`.

Запасной формат — Markdown (`.md`): блоки вида

```
ID: 147:2.4
EN: English text
RU: Русский текст
---
```

## 2. Необязательно: названия глав и разделов

Чтобы в результатах поиска показывались названия («Paper 0 — Предисловие, раздел «Божество и божественность»»), положите файл с названиями **до сборки базы** сюда:

```
data\titles\<book_id>_titles.json
```

где `<book_id>` — тот же идентификатор книги, который вы введёте при сборке (например `mybook`). Формат (на примере Книги Урантии, `data/titles/urantia_titles.json`):

```json
{
  "parts": [ {"part": 1, "en": "Part title", "ru": "Название части", "papers": [1, 31]} ],
  "papers": {
    "1": {
      "en": "Paper title", "ru": "Название главы", "part": 1,
      "sections": { "1": {"en": "Section title", "ru": "Название раздела"} }
    }
  }
}
```

Если файла нет, база строится без названий — всё остальное работает.

Если у вас есть пара EPUB-книг в том же устройстве, что у изданий Urantia Foundation, названия можно вытащить автоматически (нужен вариант «builder» программы или исходники):

```
python\python.exe tools\extract_epub_titles.py книга_en.epub книга_ru.epub data\titles\mybook_titles.json
```

(в архиве «builder» — запустите в папке программы; в исходниках — `.venv\Scripts\python tools\extract_epub_titles.py ...`). Для EPUB другого устройства названия проще подготовить вручную в формате выше.

## 3. Построить базу из окна программы

1. Положите файл `mybook.json` **в папку программы** (рядом с `start.bat`) — он появится в списке «Источник» вкладки **База данных** (блок «Построить базу заново / для другой книги»).
2. Выберите источник, модель эмбеддингов (по умолчанию `bge-m3`) и среду выполнения (по умолчанию `llamacpp-vulkan` — на видеокарте, не мешает работе за компьютером; `onnx-cpu` — на процессоре, медленнее, но работает везде и требует ONNX-файлов модели).
3. Введите **ID книги** (латиницей без пробелов, например `mybook`) и **Название книги**.
4. Нажмите **Начать индексацию** и дождитесь конца (около 15–20 минут на 15 тысяч абзацев; на небольшой книге — минуты). Прогресс виден на странице; кнопка «Отменить» безопасно прерывает сборку.
5. Если сборка идёт для книги, которая сейчас открыта, она подхватится сама после завершения.

## 4. Где лежит результат и как переключаться между книгами

```
library\
  urantia\book.db        ← готовая книга
  mybook\book.db         ← ваша новая книга
```

Каждая книга — отдельная папка с одним файлом `book.db` (в нём текст, индекс по словам и «смысловые» векторы). Папку можно копировать на другой компьютер целиком.

Переключение: в настройках `data\settings.json` поле `"active_book"` хранит активную книгу; программа показывает список книг, лежащих в `library`, и выбор активной сохраняется между запусками. Если после смены книги поиск «по смыслу» молчит, проверьте, что модель/среда в Настройках → Embeddings та же, с которой строилась эта база (она записана внутри базы, программа подставляет её сама).

## 5. Частые вопросы

- **База строится, но в результатах нет названий глав.** Файл `data\titles\<book_id>_titles.json` не найден или имя не совпадает с ID книги; положите его и пересоберите базу.
- **Русский поиск не находит словоформы.** Должен работать: русский текст лемматизируется при сборке. Если база собрана очень старой версией, нажмите «Перестроить полнотекстовый индекс».
- **Нужно ли менять программу для другого языка?** Сейчас поддерживается пара EN + RU. Поля называются `en` и `ru`; для другой пары языков потребуется доработка.
