    Как работает поиск: краткий гид
    
      
    Всё происходит на вашем компьютере. Сначала книгу один раз готовят, потом по готовой базе ищут за доли секунды.

    Готовая база
    
      
    
      
      
        
    1. Исходный файл. Книга приходит одним файлом (urantia_bilingual_rag.json): список абзацев. У каждого есть номер вида 147:2.4 (глава:раздел.абзац), английский и русский текст. Названия глав и разделов берутся отдельно из электронных изданий (EPUB).
      2. 
        
    2. Проверка. Для каждой записи проверяется, что есть все поля, номер записан верно, а хотя бы один из текстов не пуст. Битые записи пропускаются, причина пишется в logs\index.log.
      3. 
        
    3. Складывание в базу. Абзацы записываются в один файл book.db (SQLite) в порядке чтения. У каждого абзаца есть адрес (документ:раздел.абзац) и сквозной номер по книге; по этому номеру кнопка «Контекст» берёт соседние абзацы. Туда же попадают названия глав и разделов.
      4. 
        
    4. Словарные формы. Русский текст разбирается морфологией (pymorphy3): «агондонтеров» и «агондонтерам» становятся «агондонтер». Поэтому русский поиск находит слово в любой форме.
      5. 
        
    5. Индекс по словам (FTS5). Строится указатель, как в конце книги: для каждого слова указано, в каких абзацах оно есть. Индексируются английский текст, русский текст, русские словарные формы и названия глав.
      6. 
        
    6. Векторы смысла. Нейросеть-эмбеддер (по умолчанию bge-m3) превращает каждый абзац в набор чисел — «координаты смысла». Тексты близкие по смыслу получают близкие координаты, на любом из двух языков. Английская и русская версии абзаца кодируются отдельно, поэтому русский вопрос находит и русскую, и английскую версию. Числа сжимаются (int8), чтобы база была меньше.
      7. 
        
    7. Завершение. В базу записывается «паспорт» (какой моделью построены векторы), и готовый файл атомарно ставится на место: недостроенная база не подменит рабочую. Это самый долгий этап, около 15–20 минут на всю книгу.
      8. 
        
    8. Словарь терминов (по желанию). Программа сопоставляет русские и английские слова по тому, как часто они встречаются в парных абзацах («Вселенский Отец» ↔ «Universal Father»). Он нужен режиму «Вопрос к тексту».
      9. 
      
    

      
    Часть 2. Как ищет каждый режим
    

      
    
        
    По словам (fts)
    
        
    Работает как указатель: берёт слова запроса и находит абзацы, где они есть.
    
        
    
          
    Запрос
    →
    
          
    Убрать служебные слова«что», «это», «what»
    →
    
          
    Русские слова к начальной форме
    →
    
          
    Найти в указателе
    →
    
          
    Ранжирование bm25
    
        
    
        
      
          
    • Фраза в кавычках "вот так" ищется точно и подряд.
      • 
          
    • Чем реже слово в книге и чем чаще оно в абзаце, тем выше абзац. Совпадение в названии главы весит больше, чем в тексте.
      • 
          
    • Подходит, когда вы знаете точное слово или имя. Не находит то, что сказано другими словами.
      • 
        
    
      
    

      
    
        
    По смыслу (semantic)
    
        
    Запрос тоже превращается в «координаты смысла», и берутся абзацы с самыми близкими координатами. Для каждого абзаца учитывается лучший из двух языков.
    
        
    
          
    Запрос
    →
    
          
    Вектор запроса
    →
    
          
    Сравнение со всеми абзацамиEN и RU, берётся лучший
    →
    
          
    Самые близкие
    
        
    
        
      
          
    • Находит абзацы, в которых нужных слов нет, но речь о том же.
      • 
          
    • Русский запрос находит английский абзац и наоборот.
      • 
          
    • Слабее на редких именах и терминах: смысловая модель может «размыть» их.
      • 
        
    
      
    

      
    
        
    Смешанный (hybrid) — по умолчанию
    
        
    Запускает оба поиска и объединяет результаты методом RRF (слияние по местам в списках).
    
        
    
          
    
            
    Поиск по словамтоп-50
    
            
    Поиск по смыслутоп-50
    
          
    →
    
          
    RRFбалл = 1/(60 + место) от каждого списка, баллы складываются
    →
    
          
    Единый список
    
        
    
        
      
          
    • Абзац, найденный обоими способами, оказывается выше всех.
      • 
          
    • Сочетает точность слов и понимание смысла. На проверочных запросах это лучший вариант, поэтому он стоит по умолчанию.

    Вопрос к тексту
    
        
    Программа не просто ищет, а отвечает по прочитанным абзацам. Нужна языковая модель (LM Studio или другой подключённый провайдер).
    
        
    
          
    Вопрос
    →
    
          
    План поискаключевые слова EN/RU + смысловая фраза
    →
    
          
    Проверка словпо словарю книги
    →
    
          
    Слова + смысл + RRF
    →
    
          
    Контекстсоседи, разделы
    →
    
          
    Ответ со ссылками
    
        
    
        
      
          
    1. План поиска. Модель превращает вопрос в ключевые слова на обоих языках и перефразированную смысловую фразу.
      2. 
          
    2. Проверка слов. Каждое слово сверяется с реальным словарём книги: есть ли оно и в скольких абзацах. Придуманные моделью слова отбрасываются, слова пользователя остаются. Недостающий перевод берётся из словаря терминов.
      3. 
          
    3. Поиск. Три списка: по проверенным словам, по смысловой фразе плана и по самому вопросу. Сливаются методом RRF.
      4. 
          
    4. Гарантия редких слов. Абзацы с редким словом из вопроса (оно встречается лишь в нескольких абзацах) обязательно попадут к модели, даже если слияние поставило их ниже.
      5. 
          
    5. Сбор контекста. К найденным абзацам добавляются соседние, а для вопросов вида «перечислите…» — целые разделы. Всё обрезается по размеру, который вмещает модель.
      6. 
          
    6. Ответ. Модель отвечает только по этим абзацам и ссылается на номера вида [147:2.4]. Выводы, которых нет в тексте прямо, помечаются.
      7. 
        
    
      
    

      
    
        
    Анализ перевода
    
        
    Это не поиск, а прямая выборка: вы указываете главу или раздел (например, «Paper 147 Section 2»), и программа берёт эти абзацы по номерам.
    
        
    
          
    Глава / раздел
    →
    
          
    Порции по размеру контекста
    →
    
          
    Сравнение EN и RU моделью
    →
    
          
    Перепроверка замечанийцитата должна быть в тексте
    →
    
          
    Отчёт (Markdown)
    
        
    
        
    Ищутся пропуски, добавления, искажения смысла и неверные термины. Показываются только существенные расхождения.

Подстановки в фигурных скобках {…} программа заменяет сама — их можно переставлять, но нельзя придумывать новые. Нажмите на заголовок промта, чтобы раскрыть его.
