## Сделано (сервер, код есть)

- **Параметры ответа** — `app/options.py`: единый список настроек с границами, подсказками на русском и значениями по умолчанию, равными прежнему поведению: сколько абзацев передавать (12), доля контекста под источники, число кандидатов по словам / по смыслу (0 = авто), константа RRF (60), соседние абзацы (0–2), порог релевантности, язык абзацев для модели (EN+RU / RU / EN), язык ответа, число ключевых слов в плане поиска, размер порции при проверке перевода (8), второй проход проверки, порог важности замечаний, режимы «рассуждения», «помеченные выводы», подготовка запроса. Значения проверяются при сохранении (`/api/settings` отвечает понятной ошибкой 400), применяются со следующего вопроса без перезапуска. Форма для интерфейса отдаётся через `GET /api/options`.
- **Промты** — `app/prompts.py`: все 10 запросов к модели вынесены в реестр: основная инструкция, правила выводов, правило «по-русски», **новое «Оформление ответа»** (Markdown), шаблон сообщения с вопросом и источниками, напоминание про выводы, план поиска, проверка перевода (3 промта). У каждого — название, описание, список допустимых подстановок `{…}`, проверка при сохранении (лишние/отсутствующие подстановки → ошибка), хэш-версия «стандартный · abcd1234 / свой · …», оценка токенов. Правки хранятся в `settings.json` (`prompts`, только отличия от стандартных). Неверная правка не ломает вопрос: берётся стандартный текст и возвращается предупреждение. API: `GET /api/prompts`, `PUT /api/prompts/{id}`, `POST …/reset`, `POST /api/prompts/reset-all`.
- **Наборы (пресеты) промтов**: сохранение / загрузка / переименование / удаление, экспорт и импорт файлом (`data/prompt_presets.json`; импорт не затирает существующие наборы и отбрасывает неверные промты). API: `/api/prompt-presets…`, `/api/prompt-presets-export`, `/api/prompt-presets-import`.
- **Вопрос к тексту** использует все новые параметры и промты и возвращает полный **снимок эксперимента**: точные отправленные system- и user-сообщения, версии промтов и имя набора, модель, температуру, лимит токенов, режим рассуждения, длину контекста, параметры поиска (k, кандидаты, RRF, соседи, порог, сколько найдено / осталось / передано), поисковые слова, время по этапам, статистику модели, версию программы и дату.
- **Анализ перевода**: размер порции, второй проход, порог важности и три промта работают; тоже возвращает снимок эксперимента.
- **История** (`data/history.db`): новые поля снимка, оценки (−1/0/+1) и заметки с автоматическим добавлением столбцов в старую базу; `POST /api/history/{id}/rating`; фильтр по оценке и сортировка по оценке в `GET /api/history`; сравнение двух записей `GET /api/history/compare?a=&b=` (различия параметров, различия строк промтов, метрики скорости/токенов/источников); **точный повтор** запроса из сохранённого снимка (`replay` в запросе задачи). Для поиска тоже сохраняется краткий снимок.
- **Тесты** (написаны и проходили при последнем запуске): параметры и промты — 21, вопрос к тексту — 24, анализ перевода — 24.

## Исправления 07.10.2026 (вечер): OpenRouter, подписи этапов, скорость, подготовка запроса

1. **Ошибки OpenRouter** (`app/llm/provider_errors.py`): тело ошибки и ошибка посреди потока разбираются полностью (текст, компания-поставщик, исходное сообщение). Понятно сказано, кто виноват: «Провайдер модели (Nvidia) перегружен» — это нехватка мощности у поставщика, а не ваш лимит; «дневной лимит бесплатных запросов вашей учётной записи» и «в минуту» — это лимит аккаунта. Подсказки: подождать минуту, другая бесплатная модель, «openrouter/free», запасные модели, пополнение баланса. Бесплатные модели при 429 повторяются один раз (если сервер не просит ждать дольше); лимит аккаунта не повторяется вовсе. У провайдера появилось поле «запасные модели» (до 5): при перегрузке или сбое программа пробует следующую; для OpenRouter список уходит ещё и в его `models`. В статусе и в итоге видно, какая модель ответила. Карточка OpenRouter показывает состояние счёта (`GET /key`: бесплатный уровень, потрачено, лимит) только если облако разрешено и ключ есть. Если поток оборвался после части ответа, задача получает понятную ошибку, а полученная часть показывается с пометкой «Ответ оборван» и сохраняется в истории. Рядом с настройкой модели по задачам — подсказка, что «Подготовка запроса» тратит лишний запрос.
2. **Подписи этапов**: «отправка в {провайдер} · {модель}» везде (вопрос, перевод); «LM Studio» остаётся только там, где речь именно о нём.
3. **Скорость**: «генерация» = токены / (время − ожидание первого токена; рассуждение считается первым токеном). Строка: «генерация 16.4 ток/с · до первого токена 10.6 с · всего 19 с · 3175 → 233 ток.». Проверено на живой LM Studio: 24.1 / 24.0 / 24.2 против 24.07 / 23.99 / 24.19 в её журнале (разница до 0.3%); старая формула давала 17.
