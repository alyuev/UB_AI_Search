# Bilingual Text Analyzer

Программа для работы с двуязычной книгой (английский + русский) у вас на компьютере, без интернета и без облака. Сейчас в комплекте — «Книга Урантии» (14 585 абзацев в двух языках).

Что она умеет:

- **Искать** по тексту: по словам, по смыслу или вместе (русский запрос находит английский абзац и наоборот).
- **Отвечать на вопросы по тексту**: нейросеть читает найденные абзацы и отвечает со ссылками на них.
- **Проверять качество перевода**: сравнивает русский и английский абзацы и показывает только существенные расхождения (пропуски, добавления, искажения смысла, неверные термины).
- **Готовить базу** из вашего файла с двуязычным текстом (см. `docs/new_book_howto.md`).

Всё работает локально. Поиск не требует ничего, кроме самой программы. Ответы на вопросы и проверка перевода требуют программу **LM Studio** с загруженной языковой моделью (см. ниже).

---

## Запуск

1. Распакуйте архив в любую папку (можно с пробелами и русскими буквами в пути; права администратора не нужны).
2. Дважды щёлкните **`start.bat`**.
3. Откроется браузер со страницей программы (адрес вида `http://127.0.0.1:8765`; если порт занят, программа сама выберет следующий свободный). Окно с чёрным фоном — это сама программа: пока оно открыто, всё работает. Чтобы выйти — закройте это окно.

Если браузер не открылся сам, скопируйте адрес из чёрного окна в адресную строку.

## Вкладки

### Поиск
Введите запрос и выберите, что сделать:

- **Поиск** — найти абзацы. Режимы:
  - *hybrid* (по умолчанию) — слова + смысл вместе, лучший вариант в большинстве случаев;
  - *fts* — только по словам (точные формы, быстро); фразу в кавычках `"вот так"` программа ищет точно;
  - *semantic* — только по смыслу.
  Каждый результат — карточка: номер (`147:2.4` = Paper 147, раздел 2, абзац 4), английский и русский текст рядом, найденные слова подсвечены. Кнопки: **Контекст** (соседние абзацы), **Весь абзац** (развернуть фрагмент).
- **Вопрос к тексту** — задайте вопрос по-русски или по-английски. Программа найдёт нужные абзацы и попросит модель ответить *только* по ним. Номера в квадратных скобках `[0:1.2]` — ссылки на абзацы-источники (клик разворачивает абзац). Если данных в книге не хватает, модель должна прямо об этом сказать.
- **Анализ перевода** — введите, что проверить: `Paper 147 Section 2`, `Документ 147 раздел 2`, `147:2`, `147:2.4-11` (абзацы с 4 по 11), `весь Paper 147`. Проверка идёт по порядку, показывается ход работы. В отчёте — только существенные проблемы с цитатами из английского и русского текста; отчёт можно сохранить в Markdown. Помните: проверка большого раздела занимает минуты (модель читает абзацы небольшими порциями). Для проверки лучше брать небольшие фрагменты.

### База данных
Вверху — карточка **«Состояние базы»**: готова ли база, сколько в ней абзацев и векторов, есть ли названия глав, цел ли файл. Зелёные галочки — всё хорошо, жёлтые ⚠ — есть замечание, и рядом сразу предлагается нужное действие. Если базы нет, вы увидите крупное сообщение «База ещё не построена» и форму сборки.
Ниже — **«Действия»**:
- **Перестроить полнотекстовый индекс** — пересобирает только поиск по словам из уже сохранённых абзацев (около минуты; поиск продолжает работать, векторы не трогаются). Нужна, например, если в карточке написано «индекс без названий глав». Кнопка просит подтверждение прямо на странице.
- **Построить базу заново / для другой книги** (раскрывающийся блок) — полная сборка из исходного файла (около 20 минут для «Книги Урантии»; видны этапы, проход EN/RU, скорость и оставшееся время). Кнопка **Отменить** безопасно останавливает сборку: прежняя база остаётся нетронутой. Если база этой книги уже есть, программа спросит подтверждение.
Если страницу закрыть и открыть снова во время работы, ход выполнения покажется опять. Подробно — в `docs/new_book_howto.md`.

### Настройки
Страница разбита на пять блоков во всю ширину; сверху — меню для быстрого перехода, блоки можно сворачивать. Изменения действуют со следующего вопроса, перезапуск не нужен.

- **Модель LLM** — «Провайдеры» (откуда берётся модель: LM Studio, Ollama, llama.cpp, любой совместимый сервер или облако OpenRouter; у каждого карточка со значком 🖥 / ☁, кнопками «Сделать активным», «Проверить соединение», «Модели…», «Изменить», «Удалить»), выбор модели со списком, температура, лимит длины ответа, таймаут. Ниже, в «Параметрах ответа», можно назначить другой провайдер отдельно для ответа, проверки перевода и подготовки запроса. Подробно — в разделе «Облачные и локальные модели».
- **Промты** — тексты инструкций, которые программа отправляет модели (10 штук: основная инструкция, правила выводов, оформление ответа, шаблон сообщения с вопросом, план поиска, три промта проверки перевода и др.). У каждого есть описание, список допустимых подстановок `{…}` (нажмите на «чип», чтобы вставить его в место курсора), счётчик знаков и токенов и метка версии («стандартный · abcd1234» или «свой · …»). Кнопки: **Сохранить** (ошибки показываются красным под полем — например, если удалена обязательная подстановка), **Сбросить к стандартному**, **Показать стандартный** (рядом с вашим текстом, различия подсвечены). Менять промты не обязательно: стандартные проверены. Неверная правка никогда не ломает вопрос — программа возьмёт стандартный текст и предупредит.
  - **Наборы промтов** — «Сохранить текущий набор как…», «Загрузить», «Переименовать», «Удалить», «Экспорт в файл», «Импорт из файла» (импорт не затирает ваши наборы). Рядом видно активный набор и пометку «изменён», если после загрузки вы правили тексты. «Сбросить всё к стандартным» возвращает все тексты (наборы остаются).
- **Параметры ответа** — сколько абзацев отдавать модели, сколько свободного контекста занимать источниками, сколько кандидатов брать из поиска, соседние абзацы, порог релевантности, язык ответа, рассуждение модели, помеченные выводы, подготовка запроса, размер порции и второй проход при проверке перевода. У каждого поля есть подсказка, допустимые границы и кнопка «по умолчанию»; неверное значение подсвечивается с понятным пояснением.
- **Поиск** — веса полей (заголовки важнее текста и т. п.), режим «любое слово / все слова», отбрасывание служебных слов. Менять обычно не нужно.
- **Embeddings** — какая модель и на чём считает «смысл» (по умолчанию bge-m3 на видеокарте через Vulkan).

### Оформление ответов (Markdown)
Модель оформляет ответ списками, **жирным** и *курсивом* — программа показывает это красиво. Флажок **«Показывать оформление (Markdown)»** над результатами переключает на «сырой» текст (выбор запоминается). Разметка безопасна: чужой HTML не выполняется, картинок нет, ссылки открываются только `http`/`https`. Номера `[0:1.2]` остаются кликабельными. Чтобы модель писала простым текстом, замените промт «Оформление ответа» на «Пиши простым текстом без разметки.».

### История и эксперименты
Кнопка **«История»** открывает панель прошлых запросов (поиск, фильтр по виду и по оценке, сортировка «сначала с лучшей оценкой»). В открытой записи:
- **👍 / 👎 и заметка** — отметьте, какой результат лучше; метка видна в списке.
- **«Параметры этого запроса ▸»** — всё, что влияло на ответ: модель, температура, рассуждение, найденные и переданные абзацы, поисковые слова, время по этапам, скорость (токенов в секунду), задержка до первого слова, версии промтов и набор, а также **точные тексты, отправленные модели** (кнопки «Копировать»). У старых записей написано «параметры не сохранены».
- **«Повторить запрос»** — точный повтор с теми же промтами, моделью и параметрами ответа (веса и режимы поиска по словам берутся текущие); **«Повторить с текущими настройками»** — обычный новый запрос.
- **«Сравнить с…»** — выберите другую запись (сначала предлагаются с тем же вопросом): ответы рядом, показатели простыми словами («вторая быстрее на 3 с»), отличающиеся настройки и изменённые строки промтов. Так удобно проверять, помогла ли правка промта или параметра.

## Настройка LM Studio (для вопросов и проверки перевода)

1. Установите LM Studio (lmstudio.ai) и скачайте любую современную модель, хорошо понимающую русский (чем крупнее, тем лучше ответы).
2. Загрузите модель в LM Studio. **Длину контекста** задайте около **16 000–32 000** токенов (в окне загрузки модели). Меньше — не поместятся источники; больше — медленнее и тяжелее для памяти.
3. Если у модели есть режим «рассуждения/thinking», его лучше **выключить** (программа сама просит выключить его в запросах; в самой LM Studio ничего менять не нужно, но если ответы приходят пустыми — выключите там).
4. В LM Studio включите локальный сервер (вкладка Developer → Start Server, адрес по умолчанию `http://localhost:1234`).
5. В программе: **Настройки → LLM → Проверить соединение**, затем выберите модель. Если выбранная модель не загружена, программа использует загруженную и честно сообщит об этом.

Без LM Studio работает всё, кроме «Вопроса к тексту» и «Анализа перевода» — они покажут понятное сообщение, а поиск продолжит работать.

## Облачные и локальные модели

По умолчанию программа работает **полностью локально**: тексты абзацев и ваши вопросы никуда не уходят, модель отвечает на этом компьютере (LM Studio). Вместо неё можно подключить другой источник модели: другую локальную программу (Ollama, llama.cpp, vLLM и т. п.) или **облачный сервис**. При обновлении программы ничего настраивать не нужно: прежние адрес и модель LM Studio сами превращаются в провайдера «LM Studio (локально)».

**Как подключить OpenRouter (облако с сотнями моделей, есть бесплатные):**
1. Создайте аккаунт на сайте openrouter.ai (откройте его сами в браузере) и в настройках аккаунта создайте ключ (раздел Keys). Для платных моделей пополните баланс; бесплатные модели (в названии есть «:free») работают без оплаты, но медленнее и с лимитами.
2. В программе: **Настройки → Модель LLM → Облачные модели → «Разрешить облачные модели…»**. Прочтите предупреждение и подтвердите. Пока вы этого не сделали, облачные провайдеры не работают вообще.
3. **«＋ Добавить провайдера» → OpenRouter**, вставьте ключ в поле (кнопка «Показать» позволяет проверить, что вставилось нужное), нажмите «Добавить».
4. В списке моделей найдите нужную (поиск по названию, фильтры «только бесплатные» и «контекст от…»; показаны размер контекста и цена за миллион токенов), нажмите на неё, затем «Проверить выбранную модель» — программа сделает крошечный запрос и покажет время ответа и стоимость.
5. Нажмите «Сделать активным». Рядом со строкой запроса появится значок «☁ Облако: OpenRouter · модель».

**Важное о приватности.**
- При работе с облаком **тексты найденных абзацев книги и ваши вопросы отправляются на внешний сервер** (например, openrouter.ai) и дальше — владельцу выбранной модели. Не включайте облако, если это не допускается.
- Ключ хранится только на этом компьютере в отдельном файле `data/secrets.json`, зашифрованным средствами Windows (привязан к вашей учётной записи Windows). Ключа нет в настройках, истории, журналах, снимках экспериментов и экспорте наборов промтов; программа никогда не показывает его обратно (только последние 4 знака). В папку для передачи другим (`dist`) файл не попадает. Если шифрование Windows недоступно, программа покажет предупреждение, что ключи хранятся без шифрования. Ключ можно вместо этого задать переменной среды `OPENROUTER_API_KEY` (для OpenAI — `OPENAI_API_KEY`).
- В журнале `logs/app.log` пишутся только адрес сервера, название модели и статус, но не вопросы, тексты и ключи.

**Деньги.** Платные модели списывают деньги со счёта на сайте провайдера. Цена указана за миллион токенов (токен — примерно 3–4 буквы). У OpenRouter программа получает фактическую стоимость каждого запроса и показывает её в строке «… · стоимость ≈ $0.0031», в результате задачи и в истории (раздел «Параметры этого запроса»). Для остальных облачных серверов стоимость оценивается по списку цен, если он известен. Анализ перевода большого фрагмента — это много запросов: сначала проверьте на небольшом.

**Как оставаться полностью офлайн.** Ничего не делайте: «Облачные модели» выключены по умолчанию. Если вы их включали — кнопка «Выключить (работать только локально)» вернёт всё назад и переключит активного провайдера на локальный. Облачные записи в истории помечены значком ☁.

**Разные модели для разных задач.** В «Параметрах ответа» → «Какая модель что делает» можно, например, оставить подготовку запроса (короткая задача) на маленькой локальной модели, а ответы получать из облака. Для каждого провайдера можно задать свои температуру и лимит длины ответа («Изменить» → «Свои параметры модели»).

**Ошибки.** Программа объясняет их по-русски: неверный ключ (401), нет средств (402), нет доступа (403), модель не найдена (404), превышен лимит (429 — программа сама повторит запрос до 3 раз), сбой на стороне сервиса (5xx), нет ответа за время таймаута, нет интернета.

## Если что-то не так

| Проблема | Что делать |
|---|---|
| Окно закрывается сразу | Откройте командную строку в папке программы, запустите `start.bat` и прочитайте сообщение; подробности в папке `logs`. |
| «Не найден python\python.exe» | Архив распакован не целиком или `start.bat` перенесён отдельно. Распакуйте заново. |
| Страница не открывается | Адрес указан в чёрном окне (`http://127.0.0.1:порт`). Антивирус/брандмауэр не должны блокировать локальный адрес 127.0.0.1. |
| «База не найдена» | В папке `library/<книга>/book.db` нет файла. Постройте базу во вкладке «База данных». |
| «База данных повреждена» | Файл `book.db` испорчен. Верните исходный файл из архива или постройте базу заново. |
| Поиск по смыслу ничего не находит, работает только по словам | Не запустился расчёт «смысла»: нужна видеокарта с Vulkan и файлы в `models` и `tools\llama.cpp`. Откройте Настройки → Embeddings → «Загрузить модель» и посмотрите сообщение. Поиск по словам при этом работает. |
| «Не удалось подключиться к LM Studio» | LM Studio не запущена или выключен сервер; проверьте адрес в Настройках. |
| «В LM Studio не загружена ни одна модель» | Загрузите модель в LM Studio. |
| Ответ модели обрывается или пустой | Увеличьте «Max tokens» в Настройках; отключите «рассуждение» у модели; проверьте, что контекст модели не меньше ~16 000. |
| Анализ перевода «ничего не нашёл» | Это нормально для хорошо переведённых абзацев: программа показывает только существенные расхождения. |

Где что лежит: настройки — `data\settings.json`, журналы — `logs\`, базы книг — `library\<книга>\book.db`. Программа ничего не отправляет в интернет.
